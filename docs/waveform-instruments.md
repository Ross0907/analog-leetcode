# Waveform instruments

`ScopeResult` in `app/components/scope-result.tsx` (also re-exported by `simulation-console.tsx`) accepts the shared `SimulationPayload` contract. It displays captures from the upstream CircuitJS1 engine and results from the existing EEcircuit/ngspice WebAssembly worker. Neither the viewer nor the FFT module evaluates a circuit or supplies fallback waveforms.

## Probes and analyses

- The result contract accepts voltage and current traces, stable IDs, descriptive names, optional node associations, and optional colors. Voltages and currents use separate plots and scales. Colors otherwise derive from stable probe identity.
- Up to 32 probes are accepted. Requests above this limit fail visibly. No fifth probe is silently discarded. An unavailable requested ngspice node or source current is an error; the normalizer never substitutes a different node.
- ngspice supports operating point, transient, DC sweep, and complex AC results. AC plots show magnitude in dB relative to 1 V (or 1 A) and unwrapped phase. A unit AC source is needed when interpreting node magnitude as voltage gain. The normalizer retains actual source/inductor branch currents provided by ngspice; requesting an unavailable device current produces an error.
- All trace arrays must match the result axis and contain finite numbers. Transient time and AC frequency must increase. The existing ngspice resource bounds and isolated worker timeout remain in place.
- The worker prepends a comment title before sending a deck to ngspice. SPICE reserves its first line for a title; this preserves voltage sources that are the first line of older challenge decks.
- Users can rename, hide, remove, and restore result traces. These controls change the displayed capture. Native editor probe controls change the next capture and restart an active live record with the updated enabled channels.
- Clicking a trace name or a plotted trace selects it and highlights its matching schematic probe; selecting a schematic probe highlights its measured trace. Selection does not hide other channels. The separate eye button controls visibility. FFT-derived channels retain their original acquisition identity for this link.
- Schematic-mode SPICE results use native probe colors and exact generated reference bindings for voltage-source/inductor currents, including AC phase. Canonical solver names and numerical values remain unchanged. Separate/custom decks never guess a connection to native probes; extend their record by editing their own analysis directive. Other native device currents remain available through Capture all probes. Current sign conventions differ for a voltage source: native current follows negative-to-positive, while SPICE `I(V...)` follows positive-to-negative.

## Live acquisition and workspace

The shared workspace offers tabs, stacked panels and side-by-side schematic/measurements. A source selector distinguishes a native capture from an actual ngspice result. Schematic-mode analysis reads the current native graph every time; separate reference/custom decks require an explicit selection and disclose that schematic edits are not reflected.

Live acquisition samples real native `ontimestep` values at the requested record interval. Continuous mode keeps a rolling window; Freeze holds that window while the solver continues. One-record mode pauses after the requested duration, preserving finite PWL/logic sequences. Time zero resets device history without changing components, wires or probe identity; Current state continues the existing simulation. The default depth is 65,536 samples per channel and the maximum is 131,072, limited by a shared 2,097,152-Float64-value storage budget including timestamps. Reduced depth is reported. Fixed ring storage drops oldest samples; UI publication is capped at two updates per second. Numeric snapshots and waveform/FFT rendering use additional bounded memory. One-shot capture retains the existing pause-on-completion behavior. See [native integration](circuitjs-integration.md) for callback lifetime, reset/edit behavior and conversion coverage.

Finite native captures use the selected target to set the solver interval and retain actual adaptive convergence steps up to the shared sample budget. Consequently the reported number of measured points can exceed the target. Reaching the budget before the requested duration is reported explicitly; the instruments use only the time range actually recorded.

## Logic analyzer

The logic view applies user-configured low and high voltage thresholds to actual acquired voltage samples. Values at/below low become 0, at/above high become 1, and the in-between band becomes X. Invalid thresholds show an error. It draws transitions only where sampled data changes state; it cannot reveal pulses missed by acquisition. Up to 16 checked channels form a bus, with the first checked channel in displayed list order as bit 0. The cursor holds the most recent actual sample at or before its displayed time, including nonuniform solver steps; uncaptured regions report no sample, and reports binary/hex, or X for an indeterminate bit. Drag horizontally across a lane to zoom into that time interval; double-click or **Reset view** restores the full record. Zooming preserves the recorded transition timestamps. More than 6,000 transitions per channel produces a visible shorten-window notice rather than an invented compressed waveform.

## Auto set, time windows and readouts

Every instrument has **Auto set**. Scope, Bode and DC curve plots restore their full configured axis window and fit the visible traces vertically. FFT additionally selects a power-of-two record length supported by the largest real sample interval, clears frequency cropping, and restores Hann/DC-removal/dB defaults. Logic restores its time window and lane spacing, and places thresholds at 20% and 80% of the captured voltage range; a constant capture keeps valid thresholds because it cannot establish separate logic levels, or restores the documented 0.8 V / 2 V defaults when thresholds are invalid. DC readouts restore automatic engineering units.

Time-domain plots offer **0 → latest sample**, **Fit samples**, and **0 → requested duration** when the workbench supplies a duration. The capture supplies relative timestamps. Requested regions outside the actual captured interval remain blank; the logic renderer and cursor do not extrapolate states into those regions. Changing the display window does not request or fabricate additional samples.

The DC readings view presents the latest actual sample for transient data and clearly labels its timestamp. It does not treat that sample as a calculated operating point. True operating-point results retain their own DC label. Lessons can explicitly start in this readout-only view; the general default remains the oscilloscope.

## Oscilloscope

The timebase selector, zoom buttons, horizontal position slider, and Shift-drag/middle-drag pan inspect the captured record. Vertical scale and autoscale are available per physical unit. Dragging a rectangle inside the plot zooms both axes to that area; log-frequency plots select their frequency interval in logarithmic screen coordinates. Double-click, **Reset**, or R restores the full record. Alt-drag moves the nearest time cursor, and a click positions it. Arrow keys move cursor A; Alt+arrows move cursor B. Time cursors show delta time, reciprocal delta time, and each visible trace's interpolated B-minus-A amplitude. Independent amplitude cursors display a vertical difference. A trigger channel, level, and rising/falling edge identify crossings in the recorded waveform; **Find first edge** centers the capture on an existing crossing. This is a post-capture trigger search, not hardware acquisition triggering.

Scale selectors, detailed measurements, cursors, trigger and horizontal-position controls are grouped in a collapsible section below the waveform. For time records, minimum, maximum, peak-to-peak, mean, and RMS use the visible samples. Mean and RMS integrate the piecewise-linear waveform over actual time intervals, avoiding sample-density bias from adaptive SPICE timesteps. Period and midpoint-threshold duty estimates require at least two complete consistent periods, three rising crossings, and more than eight samples per cycle at the largest interval. Undersampled, nonperiodic, constant, and invalid records show unavailable values. Frequency-domain plots do not present RMS/mean of dB or phase as physical waveform measurements.

## Presentation and trace styles

All instrument chrome, canvas backgrounds, grids and axes follow the application light/dark theme. Bright trace colors are darkened by preserving their RGB proportions in light mode for contrast; the chosen color remains stored unchanged. Right-click an actual rendered trace or its channel name to open a compact color and line-thickness menu. The channel eye button and logic channel names also support Shift+F10. The scope menu additionally contains rename, coupling and remove controls. Styles are retained by stable trace identity while switching measurement views; reset changes the view, not the chosen style. The trace menu also provides a vertical **Display offset** in that trace's physical units. **Stack traces** assigns nonoverlapping display ranges, and **Clear offsets** restores original positions. Each shifted channel displays its offset. Plot coordinates and axis cursors reflect those offsets; the numerical table, crossing/frequency calculations, FFT input and logic thresholds continue using the unshifted measured values.

The **Traces** selector switches scope, FFT, Bode and DC curves between overlap and separate plots. Separate plots have independent, labeled amplitude axes and preserve measured amplitudes; they do not add an offset to the signal or change its FFT. Logic offers separate lanes or overlapping 0/X/1 traces, with bus membership independent of trace selection. DC readouts offer a compact group or separate rows. An individual separate plot can maximize and export its own PNG.

Each selected instrument can maximize within the workbench, hiding sibling plots while preserving their state. It does not invoke the browser Fullscreen API. **Save instrument PNG** exports the current canvas or digital lanes with trace names, offset notes and time/threshold metadata. All lanes are snapshotted before SVG rasterization so live updates cannot combine separate acquisitions in one image. DC exports contain the actual readouts. The PNG does not include unrelated page content or other instruments.

Transient results initially show the oscilloscope, or the explicit lesson-preferred readout. Spectrum and Scope + FFT remain explicit choices. AC results show Bode magnitude/phase, DC sweeps show the curve tracer, and operating points show numeric values. Area zoom, reset and trace styling are shared by scope, FFT, Bode and DC plots. Logic lanes zoom their time axis while keeping discrete 0/X/1 levels.

## FFT

The spectrum uses the established MIT-licensed [`fft.js`](https://github.com/indutny/fft.js) transform. All acquired channels are transformed and displayed together; the channel selector chooses the highlighted trace and its marker/metrics without removing other traces. Linear voltage and current magnitudes use separate axes. The user selects a power-of-two record length (64–131072), Rectangular/Hann/Hamming/Blackman window, DC removal, linear/log frequency, linear/dB peak magnitude, frequency span, and marker. Record lengths use the final portion of the capture. There is no zero padding that could suggest additional measured resolution.

The initial FFT depth is the smaller of 16,384 and the largest supported power-of-two length. An explicit user selection takes precedence and remains selected when a deeper acquisition replaces the result. This gives dense captures a useful initial record while retaining honest lower-depth display for short records.

Uniform final records retain their actual samples and original sample spacing, even when an earlier part of the acquisition contains a gap. Otherwise, adaptive records are explicitly interpolated at the largest recorded time interval, with a visible interpolation warning. The transform refuses a record too short for the requested length at that interval. When a requested depth is unsupported, the viewer keeps the largest supported spectrum visible, labels both requested and displayed lengths, and offers a denser actual acquisition through the workbench. It never relabels a shorter transform as the requested depth. The request considers raw sample count, the largest interval and the shared acquisition memory budget; at the budget limit, the viewer explains the supported depth instead of repeating an impossible request. Frequency resolution is sample rate divided by FFT length; Nyquist is half the sample rate. Magnitude is one-sided peak amplitude with coherent window gain correction; DC and Nyquist bins are not doubled. dB is relative to one trace unit, clamped at −300 dB for display.

`ScopeResult` exposes optional controlled `selectedTraceId`/`onSelectTrace`, `view`/`onViewChange`, and `fftLength`/`onFftLengthChange` props. `onRequestCapture` receives `{ minimumSamples, fftLength, reason }`; the workbench performs a real acquisition using the currently selected solver and preserves the selected Spectrum view and requested depth across the result replacement.

The dominant bin is reported only for a resolved signal with at least three cycles and sufficient samples per cycle. THD, SNR, SINAD, SFDR, and harmonic amplitudes are deliberately gated: a uniform coherent periodic capture, Rectangular window, at least 256 samples, at least eight cycles, and at least 16 samples per cycle. THD includes harmonics 2–5 below Nyquist. SNR, SINAD, and SFDR compare spectral power; the Nyquist bin receives its full RMS energy, since its samples do not have a separate negative-frequency partner. Residual power and spurs below the numerical floor return unavailable ratios rather than infinite SNR. These metrics characterize the simulated capture, not a hardware noise specification. Other records explain why the metrics are unavailable.

## Validation

`tests/instrument-interactions.test.mts` checks reversed/clamped area selection, logarithmic interval mapping, trace hit-testing, light-theme contrast, display-offset separation, fit windows without extrapolated samples, automatic thresholds/FFT length, and nonuniform logic timestamps after zoom. `tests/e2e/instrument-controls.spec.ts` checks unchanged numeric readouts after offsets, Auto set, requested time ranges, workbench-only maximize/restore, and valid PNG exports for scope/FFT/logic/DC. `tests/waveform-analysis.test.mts` checks analytical ramp integration on adaptive time intervals, sine frequency and duty, cursor interpolation, all four window gains, DC/Nyquist normalization, known harmonic distortion, sparse/noncoherent record guards, stable colors, and a 131,072-point coherent FFT. `tests/circuitjs-acquisition.test.mts` checks ring wrap/order/memory, actual callback readings, reset handling, callback restoration and freeze without solver pauses. `tests/logic-analysis.test.mts` covers threshold edges, unknown states and bus bit order. `tests/circuitjs-analysis.test.mts` checks native graph/value mapping, polarity, source phase and unsupported-model failures. `tests/simulator-results.test.mts` checks 32 simultaneous nodes, exact sample preservation, current units, missing node and invalid-axis errors, DC sweeps, and complex AC phase unwrapping. `tests/simulator-policy.test.mts` retains deck-containment and output-bound tests.

The result tests also execute the actual ngspice WebAssembly engine on 32 independent divider nodes and an untitled source-first deck. `tests/e2e/instruments.spec.ts` exercises native CircuitJS captures, multiple ngspice voltage/current probes, Bode/DC plots, rectangular zoom/reset, actual rendered-trace context menus and persistent styles, light/dark canvas colors, trace management, FFT controls, live/freeze and logic views, layout changes, and fresh SPICE analysis after editing a native resistor in a browser.

`tests/fft-sampling.test.mts` includes the real ngspice lesson 36 capture recorded in `tests/fixtures/delta-sigma-measured.json`, tests its honest supported depth, and checks a 16,384-point uniform suffix after an earlier gap against an analytical coherent sine. The fixture retains its original deck and provenance; the measured arrays are not regenerated or padded. `tests/e2e/fft-probe-selection.spec.ts` exercises high-depth lesson 36 native spectra, simultaneous probes, overlap/separate layouts, linked schematic selection, and a deeper real ngspice rerun requested from an insufficient FFT capture.

The upstream [ngspice manual](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf) documents voltage-source branch currents as `i(source)` / `source#branch`; the adapter accepts those actual result-vector forms.
