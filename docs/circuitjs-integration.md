# CircuitJS1 schematic editor and solver

AnaCode's primary schematic editor is the actual CircuitJS1 application, compiled from the official Paul Falstad repository at `5bdb1296ce6a82f79515f4f1dd1b9a86e03236f7`. The Java/GWT editor owns symbols, terminal hit testing, wiring, routing, electrical connectivity, component models, simulation, undo/redo, zoom, import/export and native scopes. AnaCode does not implement a replacement schematic backend.

The application is self-hosted under `public/circuitjs/`, framed from the same origin, and works without loading a third-party hosted editor. The native `CircuitJS1` JavaScript API provides timestep callbacks, node voltages, supported branch currents and native circuit serialization. The GPL patch exposes native terminal coordinates, node IDs, hit testing, element XML attributes, stop messages and viewport projection for probe placement and existing-grader interoperability. It also removes a redundant post-drag undo checkpoint so one native Undo reverses one edit.

The presentation adapter draws supported components using actual SVG geometry exported by the pinned official KiCad CLI. Native draw still maintains its original hit boxes, labels and terminal interaction; the adapter preserves pin identity, orientation and polarity. Native wiring, electrical nodes, device models, routing and simulation are unchanged. Unsupported components, non-DC source waveforms, four-terminal MOS variants and failed symbol loads retain native artwork. Symbol assets and their source/license inventory live in `public/kicad/`; see [KiCad symbols](kicad-symbols.md). Import/export remains CircuitJS format, and the native SVG export uses the upstream exporter.

Presentation flags disable voltage colouring, current dots and power colouring on initial load, restore and import. Native zoom commands are exposed directly so Ctrl/Cmd + wheel zooms while plain wheel scrolls the containing application. The quick component palette invokes the upstream Draw command; it does not create or maintain a second circuit graph.

## Native editing interactions

The GPL patch makes W and the Wire tool enter native routed-wire placement immediately. A first click starts the wire and the second finishes it; press-and-drag is also supported. Either endpoint may be in empty space, at a terminal or inside an existing wire. CircuitJS's native splitter creates junctions and its router supplies orthogonal segments. Escape cancels the unfinished wire. A selected component's attached wires follow mouse or arrow-key movement; affected legacy straight wires become native routed wires and directly shared component posts retain a routed connection. Undo restores the native document.

Clicking a displayed numeric component value opens an inline field. The field uses the element's existing editable property, engineering-unit parser and setter; successful edits invalidate the native analysis and participate in native undo. Enter commits and Escape cancels. The native properties dialog remains available for advanced fields. `setTheme('light' | 'dark')` applies the same theme to the native canvas, KiCad presentation, inline fields, menus and property dialogs.

## Probes and captures

The voltage tool uses CircuitJS's own hovered element and native terminal positions. All wires and terminals can be probed, including unlabeled nodes. The node selector is generated from the solver's node IDs, so a graphical crossing cannot accidentally become a connection in the adapter. Up to 32 probes can be named, colored, enabled, removed and captured together. The current tool supports native two-terminal component current. Schematic markers and plot colors agree.

The editor, probes, oscilloscope/FFT, digital threshold viewer and SPICE/check panel share one workspace. The layout selector offers tabs, stacked panels and side-by-side editor/measurements, with analysis below. Challenge probes use authored node-label recommendations. Live node badges carry the same name/color as their trace. The app theme propagates to the native editor.

**Live measurements** install a native `ontimestep` callback and copy actual accepted solver values into fixed-size Float64 ring buffers. The default target is 65,536 samples per channel; the selectable maximum is 131,072. Time plus every channel share a 2,097,152-value (16 MiB) acquisition-storage budget: capacity is `min(requested, floor(2097152 / (channels + 1)))`. A visible warning reports reduced depth. At 32 channels the maximum is 63,550 samples per channel. This budget excludes bounded published snapshots and graph/FFT display storage. Old samples are overwritten, and the most recent configured time window is published at most every 500 ms. Native adaptive timestamps remain intact; no sample is invented. A reset clears prior history. A graph edit starts a new record with surviving probes. Freeze restores the prior timestep/callback and holds the last record without stopping the circuit; live acquisition itself never pauses it.

**Capture all probes** takes one bounded record and pauses on completion. Capture sets the native maximum timestep from duration and target samples and records actual accepted timestep callbacks, retaining adaptive timestamps. It shares the 131,072-sample maximum and combined numeric-value budget; a cap/timeout reports explicitly. A circuit edit/reset, solver error or cancellation aborts one-shot capture. Native editing, capture state and saved circuit data stay local unless a user submits a grade.

The FFT accepts up to 131,072 measured samples. Its existing adaptive-time resampling warnings and conditions for valid distortion/noise metrics still apply. The logic analyzer classifies actual voltage samples using configurable low/high thresholds: at or below low is 0, at or above high is 1, and the interval between is X. It does not simulate digital gates or infer unseen transitions. Up to 16 selected channels form a binary/hex bus, with the first selected channel in displayed list order as bit 0. Drawing is limited to 6,000 transitions per channel with an explicit shorten-window notice; the bus cursor still reads the actual sample.

Save restores the native exported XML document and probe associations; Open also accepts legacy CircuitJS text files. The complete upstream example library is included. All 32 analog challenges have native documents, including two parts-only wiring exercises and six converter practice lessons. Analog model differences are labeled; exact supplied SPICE models remain available in the ngspice workspace.

## Existing grading compatibility

The five graded exercises use `circuitjs-grading.ts` to read the current native element values via upstream XML serialization, native terminal node IDs, and allowed source/model properties. Check reads a fresh snapshot every time. It converts these into the existing bounded CircuitDocument schema, validates it, and submits the real graph; the server independently verifies topology and stimulus. Unsupported components/model changes are rejected. Parts-only exercises must pass this wiring validation before a SPICE run and cannot select the separate reference deck.

General analysis uses the separate `circuitjs-analysis.ts` interoperability adapter. Each schematic-mode Run reads actual native connections and values and uses the existing CircuitDocument compiler/deck generator. The adapter supports R, ideal C (including polarized presentation), unsaturated L, ideal DC/sine voltage sources, DC/AC rails and ideal DC current sources. Current-source post 0 to post 1 and voltage-source post 1 positive/post 0 negative are preserved. Ground comes from native node 0. Source phase is converted from exported radians to SPICE degrees. Supported analyses are operating point, transient, AC (sine-source amplitude/phase is its test excitation), and DC sweep of the first source. Transient uses the shared duration/sample target; it starts a fresh ngspice response from its operating point rather than importing native runtime state. Unsupported models, source waveforms/internal resistance, capacitor ESR, inductor saturation and limited-compliance current sources stop conversion with a useful message instead of receiving a different model.

The user may explicitly choose a separate reference/custom SPICE deck for the lesson's specified advanced models. The UI states that schematic edits are not reflected in this deck. Selecting that mode is never an automatic fallback. The generated schematic deck is read-only; custom editing is enabled only in separate-deck mode. Scope/FFT accept both actual native results and actual ngspice results, with a result-source selector.

CircuitJS and ngspice remain distinct numerical engines. The native editor does not claim to import arbitrary SPICE decks or to reproduce ngspice BSIM model behavior.

## Source, license and rebuilding

`public/circuitjs/NOTICE.html` is linked from the editor and provides the exact complete source archive, GPL text, dependency notices, local patch, build script and artifact inventory. The native source and patch retain GPL-2.0-or-later licensing. The existing project MIT license does not supersede that license.

Run `pwsh -File scripts/build-circuitjs.ps1` from the repository root with Node.js and JDK 21 installed. The script checks SHA-256 hashes for the upstream archive and GWT 2.12.2 SDK before extraction, applies the reviewed API patch, compiles the generator and two browser permutations, copies resources, and records the artifact manifest. Normal frontend builds consume committed assets and require no Java/GWT installation or runtime external network access. The full original upstream archive plus exact patch and build script accompany every deployment.

Run `node scripts/audit-circuitjs.mjs` for drift detection, and the native engine/browser tests for numerical/interaction validation. Source rebuilds may change GWT permutation hashes when generator class iteration order differs; the recorded artifact inventory identifies the actual distributed build.
