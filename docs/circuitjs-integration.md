# CircuitJS1 schematic editor and solver

AnaCode's primary schematic editor is the actual CircuitJS1 application, compiled from the official Paul Falstad repository at `5bdb1296ce6a82f79515f4f1dd1b9a86e03236f7`. The Java/GWT editor owns component instances, terminal hit testing, wiring, routing, electrical connectivity, component models, simulation, undo/redo, zoom, import/export and native scopes. AnaCode does not implement a replacement schematic backend.

The application is self-hosted under `public/circuitjs/`, framed from the same origin, and works without loading a third-party hosted editor. The native `CircuitJS1` JavaScript API provides timestep callbacks, node voltages, supported branch currents and native circuit serialization. The GPL patch exposes native terminal coordinates, node IDs, hit testing, element XML attributes, stop messages and viewport projection for probe placement and existing-grader interoperability. It also removes a redundant post-drag undo checkpoint so one native Undo reverses one edit.

Common symbol bodies and palette previews use 17 actual definitions from Analog Canvas revision `85e6be67420a2395d5094325123b6debc1eb0286`. The renderer uses the upstream primitive coordinates and default transistor variants, including their polarity arrows. Two-terminal bodies keep canonical scale as lead spans grow. The upstream compact inductor and wide-input op-amp provide matched sizes and straight signed input leads without stretching artwork. DC sources use the single-cell battery; other sources use the voltage-source or pulse-source drawing with a truthful native waveform annotation, including a visible sine and an explicit PWL mark. No terminal bubbles are baked into MOS/BJT artwork. CircuitJS's own post-count list supplies junction dots only at three or more connections. Native draw maintains its hit boxes, value labels and terminal interaction; presentation preserves pin identity, orientation and polarity.

The separately attributed, 22-symbol KiCad 9.0.9 collection supplies fallback graphics. Unsupported variants, including four-terminal MOS artwork, retain native rendering. Source, license and provenance materials live in `public/analog-canvas/` and `public/kicad/`; see [Analog Canvas symbols](analog-canvas-symbols.md) and [KiCad fallback symbols](kicad-symbols.md). Import/export remains CircuitJS format, and native SVG export uses the upstream exporter.

Presentation flags disable voltage colouring, current dots and power colouring on initial load, restore and import. Native zoom commands are exposed directly so Ctrl/Cmd + wheel zooms while plain wheel scrolls the containing application. The quick component palette invokes the upstream Draw command; it does not create or maintain a second circuit graph.

## Native editing interactions

The GPL patch makes W and the Wire tool enter native routed-wire placement immediately. A first click starts the wire and the second finishes it; press-and-drag is also supported. Either endpoint may be in empty space, at a terminal or inside an existing wire. CircuitJS's native splitter creates junctions and its router supplies orthogonal segments. Escape cancels the unfinished wire. A selected component's attached wires follow mouse or arrow-key movement; affected legacy straight wires become native routed wires and directly shared component posts retain a routed connection. Undo restores the native document.

Palette DC, AC and current sources place vertically with their output above a real native ground at the return post. The source and ground form one native undo operation. This defaults new palette supplies to an explicit return; imported circuits, existing floating sources and the upstream Draw menu retain ordinary floating-source placement. Ground symbols face down the page while keeping their electrical post fixed.

Fresh bundled starters and Reset call the synchronous, idempotent `compactComponentLeads()` helper after native import. Long, axis-aligned R/C/L and two-terminal source components become 64-grid-unit native components. Real upstream `WireElm` segments join their new terminals to the original connection locations. Component objects, values, direction and ordering remain intact, followed by one native analysis request. This changes actual component spans while preserving topology; saved user documents and imported files retain their authored geometry.

Clicking a displayed numeric component value opens an inline field. The field uses the element's existing editable property, engineering-unit parser and setter; successful edits invalidate the native analysis and participate in native undo. Enter commits and Escape cancels. Clicking outside commits a valid inline value or discards invalid input, then dismisses the field. Native properties dialogs also dismiss on outside clicks. The `dismissEditors()` bridge handles clicks in the parent application outside the iframe. Editing a native source clears a previously programmed PWL table so the edited native waveform becomes authoritative.

`setTheme('light' | 'dark')` applies the selected schematic theme to the native canvas, attributed artwork, inline fields, menus and property dialogs. The workspace defaults to light paper and offers an independent light/dark/follow-site preference; plot backgrounds and controls follow the instrument/site theme.

Net labels use upstream `LabeledNodeElm`, so matching names join real native electrical nodes. The label tool offers plain text and an outlined flag; the style is persisted in a native flag bit and remains available in the native properties editor. `addNetLabel(name, style)` starts native placement, while label elements expose `getLabelStyle()` and `setLabelStyle(style)`. Label styling does not change electrical name matching.

`ensureAnalyzed()` synchronously runs pending native analysis and pre-stamping before node reads, capture or SPICE export. Upstream normally defers node allocation while paused; the bridge completes that same native work without advancing time, replacing elements or unpausing a valid circuit. It returns the native validation error when a circuit cannot be stamped. Vertical net-label presentation also avoids nearby ground marks without changing stored endpoints or its real electrical post.

## Probes and captures

The voltage tool uses native point hit testing and terminal positions, without a prior hover event. Probe grips capture their own pointer events, so moving a probe never drags the underlying label. Automatic tips choose a real wire on the same solved net; grip positions can be moved with a pointer or arrow keys, and are saved with the circuit. Dropping a voltage grip on another wire reconnects that channel and clears its previous result. Current grips stay bound to their component. All wires and terminals can be probed, including unlabeled nodes. The node selector is generated from the solver's node IDs, so a graphical crossing cannot accidentally become a connection in the adapter. Up to 32 probes can be named, colored, enabled, removed and captured together. The current tool supports native two-terminal component current. Schematic markers and plot colors agree.

`hitTest(x, y)` accepts canvas-local CSS pixels and returns an actual terminal or scalar wire attachment within 12 screen pixels, without requiring a prior hover event. Native wire segments provide the projected attachment point, component/post identity and fraction along the complete path. `getWirePath()` exposes the native straight or routed polyline, allowing probe markers to follow bends without changing circuit geometry. Component bodies do not create voltage nodes. `resetSimulation()` resets native time and device history while preserving component identity, programmed sources and run/pause state.

The editor, probes, oscilloscope/FFT, digital threshold viewer and SPICE/check controls share one workspace. The layout selector offers tabs, stacked panels and side-by-side editor/measurements. Waveforms occupy the top of the combined instrument pane; compact SPICE/grading controls and collapsible probe settings stay in that same pane. Description, schematic height, editor/instrument width and probe-settings height are adjustable with pointer- and keyboard-operated dividers. Layout preferences persist locally. Challenge probes use authored node-label recommendations. Probe-shaped schematic markers carry the same name/color as their trace and scale with the native viewport.

**Live measurements** install a native `ontimestep` callback and sample actual accepted solver values at the requested record interval into fixed-size Float64 ring buffers. Intermediate adaptive convergence steps cannot fill the ring before the requested time span is reached. The default target is 65,536 samples per channel; the selectable maximum is 131,072. Time plus every channel share a 2,097,152-value (16 MiB) acquisition-storage budget: capacity is `min(requested, floor(2097152 / (channels + 1)))`. A visible warning reports reduced depth. At 32 channels the maximum is 63,550 samples per channel. This budget excludes bounded published snapshots and graph/FFT display storage. Old samples are overwritten, and the most recent configured time window is published at most every 500 ms. Native adaptive timestamps remain intact; no sample is invented. A reset clears prior history. A graph edit starts a new record with surviving probes. Continuous mode keeps a rolling time window, and Freeze holds that record without stopping the solver. One-record mode pauses at the requested duration and retains the complete finite stimulus. Time zero resets native device history without changing the learner’s circuit; Current state continues the existing simulation. Finite lesson defaults use Time zero and One record.

**Capture all probes** takes one bounded record and pauses on completion. The maximum timestep is `duration / targetSamples`: the first reading is the first accepted step, so a non-adaptive capture returns the requested count without inventing a time-zero sample. Adaptive convergence can add real intermediate samples, subject to the explicit storage limit. Every accepted callback is recorded; no data is downsampled for acquisition.

Duration and samples per probe are always visible above the instruments. **2× longer** doubles the requested duration and sample target within their existing limits and acquires a fresh record using the currently displayed engine. When an FFT request exceeds the record's measured spacing/depth, its capture action requests a denser record while retaining the Spectrum view and requested FFT length. Scope, FFT and logic consume the same captured record. Advanced origin/continuous settings remain under **Acquisition options**.

SAR and flash-calibration lessons begin with four real, repeated PWL sequences (120 µs and 8 ms respectively); the original first-sequence grading witnesses are retained. Repeated PWL joins must have matching endpoint values and expansion remains limited to 1,024 source points. The delta-sigma filter starts with a 40 ms, 65,536-target acquisition. Existing saved starters are fingerprinted with acquisition and stimulus defaults so a curriculum update offers the current starter rather than retaining an obsolete one-cycle record silently.

Capture calls `stepSimulation(2048, 8)` to run the existing native solver in bounded batches, yielding to the event loop between calls. This bypasses animation-speed throttling during acquisition while retaining native stamping, adaptive convergence and solved currents. Changing or restoring the timestep invalidates the native integration stamp, preserving capacitor/inductor physics. Progress reports contain actual sample count, simulated time and elapsed time. Native revision and component-identity checks reject edited graphs; timestep restamping alone does not invalidate a record. A circuit edit/reset, solver error, cancellation or 60-second timeout aborts capture and restores its previous callback/timestep unless the user changed that timestep. The 131,072-sample maximum and combined numeric-value budget apply, with an explicit warning when adaptive samples or channel count reach the cap. Local Chromium regression runs collected 65,536 native divider samples in approximately 0.3 seconds; actual speed depends on the circuit and device.

Native editing, capture state and saved circuit data stay local unless a user submits a grade.

The FFT accepts up to 131,072 measured samples. Its existing adaptive-time resampling warnings and conditions for valid distortion/noise metrics still apply. The logic analyzer classifies actual voltage samples using configurable low/high thresholds: at or below low is 0, at or above high is 1, and the interval between is X. It does not simulate digital gates or infer unseen transitions. Up to 16 selected channels form a binary/hex bus, with the first selected channel in displayed list order as bit 0. Drawing is limited to 6,000 transitions per channel with an explicit shorten-window notice; the bus cursor still reads the actual sample.

Save restores the native exported XML document, probe associations, capture duration/depth and analysis settings; Open also accepts legacy CircuitJS text files. The complete upstream example library is included. All 41 analog challenges have native documents, including two parts-only wiring exercises, converter foundations and six expert designs. Analog model differences are labeled; supplied SPICE models remain available in the ngspice workspace.

## Existing grading compatibility

The five graded exercises use `circuitjs-grading.ts` to read the current native element values via upstream XML serialization, native terminal node IDs, and allowed source/model properties. Check reads a fresh snapshot every time. It converts these into the existing bounded CircuitDocument schema, validates it, and submits the real graph; the server independently verifies topology and stimulus. Unsupported components/model changes are rejected. Parts-only exercises must pass this wiring validation before a SPICE run and cannot select the separate reference deck.

General analysis uses the separate `circuitjs-analysis.ts` interoperability adapter. Each schematic-mode Run reads current native connections and exported values and uses the existing CircuitDocument compiler/deck generator. Ground comes from native node 0. Current-source post 0→1, voltage-source post 1 positive/post 0 negative, op-amp input signs, and BJT/MOS terminal identities are preserved. The supported mappings are:

| Native component | SPICE representation |
|---|---|
| R, C including polarized presentation, unsaturated L | Passive elements with supported initial conditions; capacitor ESR becomes an explicit series resistor |
| Voltage sources and rails | DC, sine, supported zero-phase square/pulse, or explicit PWL/bitstream stimuli |
| Ideal current source | DC current, with optional selected AC test excitation |
| Three-terminal ideal op-amp | Native open-loop gain and output limits, or an explicit LM741 model choice |
| Five-terminal real op-amp | LM741 with the actual positive/negative supply connections |
| Diode, BJT and MOSFET | Compatible generic/native-parameter models or selected 1N4148, BC546B/BC556B, IRFP240/IRFP9240 and CMOS90 models |
| Analog switch | Standard four-terminal SPICE SW model with the native control and on/off resistances |
| Native reusable composite | Supported constituent elements read from CircuitJS's flattened native analysis graph |

Selecting LM741 for a three-terminal op-amp creates SPICE supply rails from that symbol's output-limit settings and reports this assumption. Five-terminal op-amps use their actual wired supplies. LED and zener artwork requires an explicit diode-model choice; it is not silently converted to a switching diode. Native MOS threshold and beta are available for standard level-1 conversion; choosing a power MOS model or CMOS90 changes the ngspice model explicitly. Model assignments and limitations are shown beside the analysis. Original device files and their compatibility adaptations are documented in [standard model notices](../THIRD_PARTY_NOTICES.md#standard-spice-device-models) and [the public model inventory](../public/spice-models/README.txt).

Supported analyses are operating point, transient, AC and DC sweep. AC controls select the excitation source, magnitude, phase, decade/octave/linear spacing and point count; source phase is converted from native radians to SPICE degrees. DC sweep selects the source explicitly. Transient uses the shared duration/sample target and starts a fresh ngspice response rather than importing native runtime state. Resource limits are enforced by the current simulator policy. Unsupported components, incompatible models, source internal resistance, inductor saturation and limited-compliance current sources stop conversion with a useful explanation.

DC/sine/PWL/bitstream controls apply to the actual native voltage source through the GPL stimulus bridge. PWL uses validated numeric time/value pairs; bitstreams become explicit finite-edge voltage points, with optional repetition. The table and repeat period are serialized in native XML, used by live simulation, and read back for SPICE conversion. Native source edits clear the programmed table and stale host overrides, so later analysis uses the edited source. Programmed current requires an explicit voltage-source/transconductance circuit.

The reusable-block library delegates creation to CircuitJS's existing `CustomCompositeModel` machinery. Select components and external node labels, save a named block locally, then insert it into another exercise through the native placement command. With no selection, the whole circuit is saved; grounds remain internal. The library stores native model XML and imports it with the existing subcircuits-only option. For SPICE analysis, the bridge recursively reads constituents of custom blocks from the native graph while preserving built-in ICs such as the real op-amp as single model instances. This avoids duplicating an IC's internal devices alongside its macro-model and does not construct a second editor graph. Saved blocks and their prerequisite/recommended exercise links support later converter designs.

The user may explicitly choose a separate reference/custom SPICE deck for the lesson's specified advanced models. The UI states that schematic edits are not reflected in this deck. Selecting that mode is never an automatic fallback. The generated schematic deck is read-only; custom editing is enabled only in separate-deck mode. Scope/FFT accept both actual native results and actual ngspice results, with a result-source selector.

CircuitJS and ngspice remain distinct numerical engines. The native editor does not claim to import arbitrary SPICE decks or to reproduce ngspice BSIM model behavior.

## Source, license and rebuilding

`public/circuitjs/NOTICE.html` is linked from the editor and provides the exact complete source archive, GPL text, dependency notices, API/editing patch, source-stimulus/composite patch, build script and artifact inventory. Native source and both patches retain GPL-2.0-or-later licensing. Analog Canvas artwork/adapter, KiCad artwork and published SPICE models retain their separately documented terms; the existing project MIT license does not supersede those licenses or notices.

Run `pwsh -File scripts/build-circuitjs.ps1` from the repository root with Node.js and JDK 21 installed. The script checks SHA-256 hashes for the upstream archive and GWT 2.12.2 SDK before extraction, applies both reviewed patches, compiles the generator and two browser permutations, copies resources, and records the artifact manifest. Normal frontend builds consume committed assets and require no Java/GWT installation or runtime external network access. The full original upstream archive, exact patches and build script accompany every deployment. `node scripts/build-analog-canvas-symbols.mjs --check` independently checks the pinned catalog and generated symbol previews.

Run `node scripts/audit-circuitjs.mjs` for drift detection, and the native engine/browser tests for numerical/interaction validation. Source rebuilds may change GWT permutation hashes when generator class iteration order differs; the recorded artifact inventory identifies the actual distributed build.
